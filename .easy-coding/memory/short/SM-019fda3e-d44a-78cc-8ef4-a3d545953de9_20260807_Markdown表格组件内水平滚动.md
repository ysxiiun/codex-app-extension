# Markdown 表格组件内水平滚动

## Task Summary

- Goal: 宽屏布局启用时，Markdown 表格外壳不得越过配置后的正文宽度；表格固有内容超宽时只在表格组件内部横向滚动。
- Scope: wide-layout adapter 的表格 containment CSS、PageRuntime implementation revision、真实 WebKit 回归、fixture、桥接测试与 README/ABSTRACT 合同。
- Result: revision 11 使用稳定 `[data-markdown-table]` 约束表格外壳为当前内容宽度，复用直接表格子树作为横向滚动层；窄表、正文、页面、composer、右栏和瞬态浮层保持原生。Release 已构建、签名、幂等安装并启动，用户明确验收通过。
- Key Constraints: 不读取或修改表格内容；不新增 DOM；不依赖 CSS module hash；不强制 table 宽度、断词或 nowrap；关闭或卸载宽屏后必须恢复宿主原生 margin 与 wide-block 行为。

## Architecture and Compatibility Decisions

- Scope gate: 规则必须同时位于 `.thread-scroll-container[data-cae-wide-layout='true']` 与 `[data-selected-text-overlay-target]` 下，只命中稳定 `[data-markdown-table]`。
- Containment owner: 外壳使用 `inline-size/width/max-inline-size/max-width: 100%`、`box-sizing:border-box` 和 `margin-inline:0`，防止宿主 `calc(100% + margins)` 与负 margin 撑破正文边界。
- Scroll owner: 只给表格外壳的直接、非瞬态且包含 `table` 的原生子树设置 `max-inline-size:100%`、`overflow-x:auto`、`overflow-y:hidden` 与 inline overscroll containment；不把 overflow 放在 Markdown root 或会话页面。
- Native semantics: 不覆盖 `table` 自身 width、max-width、white-space、word-break 或单元格样式，保留宿主固有列宽和窄表行为。
- Overlay isolation: 位于任意 `[role=menu]`、`[role=listbox]` 或 `[role=dialog]` 子树中的表格 shell、scroll body 和 table 全部排除，避免瞬态交互浮层被宽屏表格规则改形。
- Runtime hot upgrade: bootstrap 与 Swift bridge 的 `implementationRevision` 同步为 11；fixture、桥接断言、README 与 ABSTRACT 同步更新，确保已打开 revision 10 页面卸载旧实现并热升级。

## Reusable Technical Memory

- 宿主已有内部滚动层时，修复外壳越界应约束组件 shell 并复用其直接 scroll body，避免另造 DOM 或把横向滚动提升到整段 Markdown。
- 对第三方 Electron DOM 的长期 selector 优先使用稳定语义 data attribute 与原生 `table`，禁止固化 CSS module hash。
- CSS 字符串断言只能证明规则形状，不能证明真实 overflow geometry。布局修复应补充 `WKWebView` 或同等级真实布局引擎测试，验证 `clientWidth/scrollWidth`、computed overflow、页面级无溢出和卸载恢复。
- 浮层隔离需要排除 role 节点任意层级中的 shell、body 与 table；只排除 shell 自身或直接子级会漏掉嵌套 dialog/menu/listbox。
- PageRuntime adapter 资源变化继续要求同步提升 implementation revision、Swift bridge、回归断言与文档，否则打开页面可能继续复用旧样式。

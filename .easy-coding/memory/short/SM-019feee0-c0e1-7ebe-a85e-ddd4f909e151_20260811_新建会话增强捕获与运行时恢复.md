# 新建会话增强捕获与 PageRuntime 生命周期恢复

## Task Summary

- Goal: 让新建会话空白页被扩展稳定捕获，使宽屏、顶部避让和中文输入保护按可用能力生效，并在首条消息生成 thread 后无缝恢复完整增强。
- Scope: Swift CDP probe、PageRuntime surface 与 observer、运行时健康恢复、wide-layout owner 资格、Core/PageRuntime 测试及 README/ABSTRACT 合同。
- Result: `thread` 与 `empty-composer` 成为一致的合格 surface；空白页允许唯一、可见且位于唯一 layout 内的安全 ProseMirror fallback；运行时/API 消失时可以 revision-safe 地重新探测和安装；空白页宽屏支持 editor 祖先链上的 composer/content 两类 width owner。PageRuntime revision 升至 13，正式安装版本经用户现场验收通过。
- Key Constraints: exact `app://-/index.html` target；不读取正文、草稿、Cookie 或完整 DOM；候选重复或隐藏时失败开放；adapter 按自身能力独立报告 healthy/waiting；卸载必须完整恢复宿主状态。

## Architecture and Compatibility Decisions

- Unified surface identity: 唯一 layout 下，有唯一 thread scroller 时为 `thread`；无 scroller 且有唯一有效 editor 时为 `empty-composer`。layout-only、重复 layout/scroller/editor 或隐藏候选均不合格。
- Safe editor fallback: 稳定的 `data-codex-composer=true` editor 优先。仅在空白页唯一 layout 内缺稳定标记时，才接受唯一、可见、可编辑且布局内的 ProseMirror 候选；Swift probe 与 bootstrap 使用等价的 count-only 资格，不读取内容。
- Independent adapter capabilities: surface 合格只建立页面身份。header 与 IME 可在空白页 healthy；wide-layout 等待 width owner；Markdown 在没有 thread/candidate 时继续 recoverable waiting，首条消息生成正文后自动生效。
- Attribute lifecycle recovery: bootstrap 在未合格 fallback 被隐藏过滤时仍观察候选及资格相关属性，避免同一节点只移除 `hidden`、`aria-hidden` 或隐藏样式后没有 child-list 事件而永久等待。
- Typed runtime recovery: performance 轮询仅在 PageRuntime 不存在或 `performanceSnapshot` API 缺失时产生专用 `runtimeUnavailable`。CDP 超时、断连、协议/解码、畸形 envelope 与 stale 错误不得触发 probe/apply。
- Late-result isolation: 恢复前同时校验 lifecycle generation、active target identity、known targets 和 per-target revision；refresh、destroy、replacement 或 reconnect 推进状态后，迟到缺失结果不能重新安装或复活旧 target。
- Empty-page width owner: wide-layout 只沿当前确认 editor 到唯一 layout 的最多 64 层祖先路径选择 `thread-composer-max-width` 或 `thread-content-max-width` owner。owner 初始缺失时有限观察该路径的 class，token 增加后恢复 healthy，移除后回到 waiting。
- CSS identity containment: 空白页 CSS 只接受 adapter 写给当前 `surface.editor` 的 `data-cae-wide-layout-editor=true` 专用 marker；隐藏或残留的宿主 marked sibling 不能通过 `:has()` 命中旁支 owner。
- Runtime migration: bootstrap 与 Swift bridge 的 implementation revision 同步为 13。非 13 的既有 runtime 先执行旧实现卸载，再原位更新 API 和重注册 adapter，防止已打开页面继续复用旧选择器、marker 或 observer。

## Risks Closed

- Surface 资格只要求 thread scroller，导致空白页所有 adapter 统一失效：已通过两态 surface 和独立 capability 合同关闭。
- React 复用节点并只改隐藏属性或 owner class，不产生 child-list mutation：已通过最小属性观察和有限祖先 class 观察关闭。
- 普通 health polling 错误被误判为 runtime 丢失并周期性重复安装：已通过 typed missing signal 与 late-result guards 关闭。
- 空白页 host marked 隐藏 sibling 触发 `:has()` CSS 外溢：已通过当前 editor 专用 marker 和反例 fixture 关闭。
- 新版空白页使用 canonical content width token，输入框仍停留 712px：已兼容受限祖先链上的 composer/content 两类 owner，并保持独立 composer 变量与完整卸载恢复。

## Reusable Technical Memory

- 对 Electron/SPA 页面，child-list observer 不足以覆盖资格恢复。若宿主会复用节点，应针对真正影响资格的有限节点和最窄属性集合观察正反向变化。
- 运行时健康恢复必须使用专用、可判定的缺失信号。不能把 transport、protocol、decode、stale 等普通错误统一解释为“运行时丢失”，否则健康轮询会放大成重复安装。
- 异步恢复写入前必须同时绑定 lifecycle generation、active identity、known membership 和 per-target revision；只比较 target ID 不能抵抗同 ID refresh 与 reconnect 的迟到结果。
- CSS `:has()` 选择器若依赖宿主 marker，可能被隐藏或残留旁支误触发。由 adapter 给当前确认节点写专用 marker，可以把 JavaScript surface 身份安全桥接到 CSS。
- Width owner 应限制在已确认 editor 到 active scope 的有限祖先链；等待原地 class 挂载时只观察这条路径，不扩大到全子树。
- PageRuntime 资源或 lifecycle 逻辑变化必须同步 implementation revision、Swift bridge、热升级测试、README 和 ABSTRACT，否则已打开页面可能继续运行旧实现。

# 外观重设计、输入稳定与 Tab 功能彻底移除

## Task Summary

- Goal: 恢复迁移前 Markdown 经典配色并重设计可操作的外观配置；彻底删除键盘焦点着色和无价值的 Tab 缩进功能；修复菜单栏重启确认、页面等待态、局部配置事务与中文输入法 Skill Enter 竞态。
- Scope: SwiftUI 设置与菜单栏、schema-2 配置/legacy 迁移、FeatureRegistry、RuntimeController/CDP bridge、PageRuntime revision 6、Markdown/IME adapters、Core/PageRuntime/UI tests、README 与架构摘要。
- Result: 外观页提供完整实时预览和经典 palette 恢复；扩展不生成焦点样式；页面结构暂缺进入 recoverable waiting 并自动恢复；配置只更新受影响 adapter；菜单重启确认脱离瞬态 popover；IME 在 window capture 阶段处理 composition/Skill Enter；Tab UI、字段、迁移特判、tombstone、测试和文档全部删除，原生 Tab 行为完全交还宿主。最终正式安装版本由用户明确验收通过。
- Key Constraints: 不修改 ChatGPT 包体或正文；不把所有 `qualified=false` 误判为 waiting；不读取或记录页面内容；不增加 Tab listener/marker/schema；不恢复焦点着色；不改变四个现役 adapter、runtimeVersion 2 或 implementation revision 6。

## Architecture and Compatibility Decisions

- Markdown classic contract: 默认值精确恢复迁移前最终 palette；标题/强调使用 `#F2C94C`，强调 weight 800，行内代码使用 `#df3079` 与旧 rgba 背景/边框，引用块使用单层粉色左边线、浅背景和嵌套复位。现有自定义 V2 配置不在启动时被覆盖，显式 Markdown reset 只重置该分区。
- Appearance UI: 保留的颜色字段都必须有色块、语义值或非法状态；宽布局为滚动编辑区配固定预览，窄布局为单列；预览不模拟键盘焦点。旧 `focusRing` schema-2 key 可被 Decoder 忽略且再保存不编码，legacy focus key 只退休不迁移为替代能力。
- Focus retirement: 产品配置、UI、adapter、bundle 和文档不包含焦点着色能力；bootstrap 只允许保留用于热升级卸载旧副作用的 retired `focus-ring` cleanup id，不加载资源或生成 marker、变量、style、observer、`:focus-visible` 规则。
- Waiting protocol: 只有 adapter 显式返回 `qualified=false/recoverable=true` 才进入 waiting；缺字段仍按不可恢复。recoverable waiting 不生成事务错误、不回滚、不显示增强降级，稳定 document-root observer 在 DOM 恢复后自动收敛 healthy。
- Local adapter transaction: wide/header/IME/Markdown 配置变化只 update/rollback 自身；global 或未指定选择集才执行四项；纯 App 外观不触发 PageRuntime。未选择 adapter 的既有硬失败不能阻断当前分区保存，被选择 adapter 自身硬失败仍必须阻断并对称回滚。
- Restart confirmation: 未启用 CDP 的 ChatGPT 重启确认使用独立原生 alert，不依赖 MenuBarExtra 的瞬态 window；popover 关闭后取消与重启仍可点击，破坏性动作只在显式确认后执行一次。
- IME Enter: listener 位于 window capture 且仅作用于 active editor/descendant；支持 macOS `key=Process + code=Enter + keyCode=229`，只消费一次 composition 后 terminal Enter，普通 Enter、编辑器外 Enter、disabled 与 uninstall 保持原生和可清理。
- Runtime hot upgrade: PageRuntime `runtimeVersion=2`、`implementationRevision=6`。revision 5 或更旧实现先 best-effort 卸载历史副作用，再原位替换 API；同 revision 注入保持幂等，四个现役 adapter 为 wide-layout、header-offset、ime-enter-guard、markdown-semantic-theme。
- Tab removal: Tab 不再是产品概念。`InputSettingsView` 只显示中文输入保护；FeatureRegistry 不保留 removed tombstone 或 qualification decision API；LegacyConfigMigrator 不特判旧 Tab key，真实未知旧字段统一走 generic unknown 且不写入 V2；fixture、测试与文档不保留负向墓碑。扩展不注册任何 Tab 事件，原生 ChatGPT/macOS 行为不需要额外兼容说明。

## Reusable Technical Memory

- 删除能力必须同时审计 UI、schema/迁移、registry/tombstone、fixtures、测试和文档。仅删除 runtime adapter 会留下错误产品认知和维护分支；残留扫描需要覆盖大小写不敏感的功能名称，而不能只扫旧 identifier。
- 已删除的 legacy key 不必永远保留专属 deprecated 分支。若 V2 从未编码该能力，旧 key 可以安全落入通用 unknown 报告并继续不写入运行配置，文档必须与这一真实语义一致。
- Swift `Codable` 默认忽略未知 key，适合兼容读取已退役 schema-2 字段；是否保留专属迁移分类应由长期产品价值决定，而不是为了负向测试墓碑。
- macOS MenuBarExtra 内的二次确认不能绑定瞬态 popover 生命周期；破坏性确认应由独立 AppKit alert/window 承载，同时让 Core 保持唯一确认动作入口。
- IME 与宿主 Skill suggestion 同时处理 Enter 时，bubble/editor listener 可能晚于宿主。应在 window capture 阶段识别 composition 序列，并严格限定 editor scope、终结事件次数和 cleanup。
- recoverable waiting 必须是 adapter 的显式结构化输出，不能通过 reason 字符串或所有 unqualified 状态推断；否则真实兼容性失败会被错误隐藏。
- PageRuntime 资源修改只有提升 implementation revision 才能替换已加载的同 revision runtime；发布验证必须包含热升级合同和正式安装包资源清单。

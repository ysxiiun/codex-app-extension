# 新建任务宽屏、owner 竞态与动态右栏连续收敛

## Task Summary

- Goal: 让宽屏布局在已有会话、新建任务空白页和两种页面之间的 SPA 转换中持续生效，同时继续按照右侧环境信息组件的实时渲染占位计算可用区域。
- Scope: CDP Target 身份、PageRuntime surface/observer、wide-layout adapter、implementation revision、Core/PageRuntime 回归测试及 README/ABSTRACT 合同。
- Result: Target 支持会话页与空白任务页两种合法结构；wide-layout 在 width owner 尚未挂载时预置宽度变量并保持 recoverable waiting，随后通过有限祖先 class 观察即时收敛；右侧栏按实际渲染组件及完整可见性链计算占位，不依赖内容多少。PageRuntime revision 升至 10，正式安装版本经用户明确验收通过。
- Key Constraints: 不读取正文、输入值或业务文案；不以固定右栏宽度或内容条目识别组件；不放宽其他 adapter 的资格；重复 layout/scroller/editor 继续失败开放；关闭或卸载必须恢复宿主状态。

## Architecture and Compatibility Decisions

- Target identity: `app://-/index.html` 必须有唯一 layout root。会话页以唯一 thread scroller 为内容锚点，composer 仍可选；无 scroller 的空白任务页才要求唯一 composer。布局单独、重复 layout/scroller 或空白页 composer 0/2 均不合格。
- Adapter qualification remains independent: Target 身份合格不代表 header、IME、Markdown 或 wide-layout 的能力锚点全部就绪；每个 adapter 继续自行返回 healthy、recoverable waiting 或 degraded。
- Empty-page wide scope: wide-layout 优先使用唯一 thread scroller；空白任务结构回退到唯一 layout root，但 width owner 必须绑定唯一 editor 的祖先链，不能选中隐藏或残留 composer owner。
- Owner mount race: 当 scroller 已存在但 width owner 尚未挂载时，在 scroller 上保留 marker、样式和全部宽度变量，使首次渲染不退回原生窄宽；健康状态保持 `qualified=false/recoverable=true`，直到 owner 真正出现。
- Same-node class race: React 可复用已挂载的 editor 祖先并原地增加或移除 width-owner class，不产生 child-list mutation。等待期间只观察 editor 到 scroller 的有限祖先，使用 `attributes=true`、`attributeFilter=[class]`、`subtree=false`；owner 资格正反向变化都通过一次 runtime transaction 同步页面几何和菜单健康。
- Persistent right rail: 右边界来自稳定原生 rail shell 内已渲染组件的真实几何。短空态组件也占位；childless shell、零尺寸、display none、visibility hidden，或从组件到 shell 任一层 opacity 0 都不占位。识别不依赖标题、列表项、文本或业务内容。
- Runtime hot upgrade: bootstrap 与 Swift bridge 的 `implementationRevision` 均为 10。adapter 资源变化必须同步提升 revision、桥接断言与文档，才能卸载已加载旧实现并原位注入新逻辑。

## Reusable Technical Memory

- 对 SPA/Electron 页面不能只观察 child-list。宿主可能复用节点并通过 class 原地完成能力挂载；等待某个结构能力时，应只观察已知有限祖先和最窄 attribute filter，并让资格增加、移除都更新运行时健康。
- “为了首帧稳定先写入宽度变量”与“健康状态已经就绪”是两件事。允许在 owner 缺失时保留无破坏的预置样式，但必须继续报告 recoverable waiting，避免 selector 永久过期被伪装成 healthy。
- 右侧组件是否占位必须基于组件容器与完整渲染可见性链，而不是内容条数、组件高度阈值或文案。空状态依旧是组件状态，不能当作组件不存在。
- Target identity、surface qualification 与 adapter capability 必须分层。放宽 Target 入口时不能顺带让所有 adapter 在锚点缺失时强制注入。
- PageRuntime 任何资源逻辑变化都要同步 implementation revision、Swift bridge、fixture 断言、README 和 ABSTRACT；否则已打开页面可能继续复用旧实现。
